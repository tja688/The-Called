# 战斗过程演出

给落地演出的 AI。本文定架构、接缝和完成标准。狗怎么扑、食人魔怎么抡，按 [`虚构设计总纲.md`](../../虚构设计总纲.md) 和 [`虚构配置表.md`](../4-数据汇总/虚构配置表.md) 在插槽里填，不在这里规定姿势。

现行合同仍是 [`表现层接缝.md`](表现层接缝.md)。字段落地时改那份的事件表，两处一起动。

## 完成时玩家能指出的事

一场战斗里，每一条结算都单独播完再播下一条。玩家能说出：谁、在回合的哪一段、对谁、点数或状态变成了什么。抽空的结算也占一拍，和打中分开。

称重胜利只在 `battle.turnStarted` 且 `won` 时出现。出牌中途总点数已经更大，只更新顶栏数字。

`npm run sim -- --compare` 的战果（hp、gold、result、battles）与现基线一致。事件 **type 序列** 也不增加、不重排。允许的改动是给已有事件加字段、改 `pointsChanged.source` 的取值。

## 接着用的东西

`PresentApp.pump` 已经把队列里的事件逐条 `await`。`Space` 把 `tw.speed` 提到 4，松键恢复。输入在队列非空时锁住。

规则侧的顺序已经是串行的，见接缝文档「关键时序」：回合开始先解封、计时，再玩家格 1→9，再敌方格 1→9，然后才称总点数。回合结束同样先玩家后敌方。一张卡的多个 op 按卡表顺序发出。`battle.effectResolved` 发在这张卡本时机的 op 之后。

`dispatch` 返回前聚合已经是这条命令的终态。演出期间 `battle.view` 是终态快照。动画只读事件字段和场景自己记下的精灵位置。

白模 `?present=dom` 继续每次事件后整屏绑终态，不播节拍。

## 现在断掉的地方

后果事件不写施动者。`damage` / `buff` 调用 `changePoints` 时把 `source` 写成 `play`，回合结束的一砸和猎箭是同一种来源。

`battle.effectResolved` 只有 `timing` 字符串，而且排在伤害、标记、移动之后。场景用它飘一个 `turnEnd`，长约 0.06 秒。

`battle.cardEntered` 同时表示从手牌落地和场上移动。移动没有 `from`。

`BattleScene` 用「上一条 type 相同则 brief」把连续的 `pointsChanged`、`occupyChanged` 收成一拍。两次结算叠在一起。

领先图标只在 `battle.turnStarted` 时写入。顶栏「己 / 敌」每帧读视图，已经是活的。

驻场和地图效果的点数变化由 `flushPoints` 发出，`source` 为 `aura` 或 `map`，不写是哪张卡、哪条地图效果。

计时减 1 没有自己的事件。引爆会在 `turnStarted` 之前以该卡的 timer 效果事件出现。

## 决定

因果写在后果事件上。播放器按到达顺序逐条演，不缓冲、不重排、不并行两张卡的结算。

`effectResolved` 留在 op 之后，当作这张卡本时机的收束。把它提前会打乱基线里的 type 序列。

不新增战斗事件 type。计时剩余写进已经存在的 `battle.turnStarted`。

易伤的 25% 加进同一次 `changePoints`，仍是一条 `pointsChanged`。加成数字放在这条事件的字段里，演出要拆成两下就在这一条的 `await` 里面串行，不再发事件。

保护挡住伤害时，现在只发 `statusRemoved`，不发 `pointsChanged`。保持这样，给 `statusRemoved` 补上因果即可。

## 事件字段

落在 `src/domain/battle/events.ts`。展示名仍由表现层用 `defId` 查虚构配置表，事件里不写中文名。

```ts
interface Cause {
  actor: string
  defId: string
  timing: 'play' | 'enter' | 'leave' | 'turnStart' | 'turnEnd' | 'timer' | 'active' | 'onCover'
  op: string
}
```

| 事件 | 新增 |
|---|---|
| `pointsChanged` | `cause?`。`vulnerableBonus?`：本次因易伤多减的点数，没有则为 0。`source` 改为这次结算的真实时机；驻场重算仍是 `aura`，地图仍是 `map`，覆盖扣点仍是 `cover`，遗物仍是 `relic` |
| `statusAdded` / `statusRemoved` | `cause?` |
| `cardEntered` | `motion: 'place' \| 'move'`。`move` 时带 `from`。`cause?` |
| `cardRemoved` | `cause?`。已有 `reason` |
| `occupyChanged` | `cause?`。化身入场立刻 +1 带上化身的 `enter`。回合开始按身体数回满不带卡，`cause` 空着 |
| `resourceChanged` | `cause?` |
| `effectResolved` | `hit: boolean`。本时机至少有一条带同一 `actor` 的后果则为 true；邻格没有目标、标记重复点不上，均为 false |
| `turnStarted` | `timers: { card: string; defId: string; left: number }[]`。这是计时走完、引爆事件已经发出之后，场上还剩的计时 |

`flushPoints` 发出的 `pointsChanged` 增加 `auras?: { card: string; defId: string; n: number }[]` 和 `mapEffect?: string`。这是变化之后的贡献列表，不是再拆成多条事件。净变化仍是这一条的 `before` → `after`。

`Cause` 从 `runEffects` 的当前卡和当前时机传进 `changePoints`、`addStatus`、`stripStatus`、`relocate`、`removeCard`。覆盖、离场连锁、打出监视（EC.12、EC.21、PC.N11、PC.B07 这类）在调用点写自己的 `cause`，`op` 用现有 op 名。

## 播放

只改像素战斗场景。队列顺序就是演出顺序。

每一条后果 `await` 完再返回，下一条才能开始。同一条内部可以有前后两下（例如先基础伤害再易伤加成），两下之间也 `await`。

收束规则，用场景里一个布尔记下「本张卡这一时机是否已经播过后果」：

- 带 `cause` 的后果把布尔设上，并按 `cause` 演。
- `effectResolved`：`hit` 为真则短暂停一下，表示这张卡这一时机做完了；`hit` 为假则用另一档更短的停顿，表示结算过、没有落到目标上。然后清掉布尔。
- `turnStarted`：先按 `timers` 把还在走的计时各亮一拍，再处理 `opening` / 普通换回合 / `won`。
- `settled`：单独一拍。`avatarCost` 和 `reason` 都要能看出来。`lead` 是称重，`clear` 是场上没有敌方卡。

删掉 `lastType === ev.type` 的 brief。连续两次 `-2` 是两次结算。

`layoutHand` 的 `Promise.all` 只用于把手牌排齐，放在抽牌或出牌事件的末尾。结算飘字不进这个 `all`。

`Space` 只提高补间速度。快进时仍然按同一顺序走完每一拍。

领先图标每帧读 `battle.view.leading`。顶栏数字继续读 `playerFinal` / `enemyFinal`。这两个都是终态事实，可以绑 HUD，不能用来补「刚才谁打的」。

主动按钮的不可用原因记在场景里：还没有 `battle.activated`，且 `legalActivates` 为空，就是没有可指定的目标；已经收到过 `battle.activated`，就是用过了。不新增查询。

时长由落地时定，约束只有一条：默认速度下，一次结束回合里大约八条后果，整段仍是连续的快放，玩家能读完每一下的施动者和数字。空收束比打中更短。

## 插槽

`BattleScene` 按 `cause.op`、`cause.timing`、`motion` 分派函数。函数签名接收事件字段（施动者 id、目标 id、前后点、格、`from`）。姿势在函数体内填。

至少分开这些函数，允许先用占位（点亮施动者、目标飘 `before→after`、虚构名）：

| 插槽 | 何时 |
|---|---|
| 标记加上 / 标记揭掉 | `op` 为 mark / unmark |
| 减点 / 加点 | `pointsChanged` 且 `source` 不是 `aura`/`map`。`vulnerableBonus > 0` 时在同一条里先播基础再播加成 |
| 保护挡下 | 本应减点却只来了 `statusRemoved` 且 status 为 protected |
| 易伤、封印、解封、返魂 | 对应 status |
| 落地 | `cardEntered.motion === 'place'` |
| 移动 | `cardEntered.motion === 'move'`，从 `from` 走到 `cell` |
| 覆盖、平点 | 已有 `cardCovered`，先于离场和落地 |
| 空收束 | `effectResolved.hit === false` |
| 计时剩余 | `turnStarted.timers` |
| 称重胜利 | `turnStarted.won` |
| 费用回满 | 回合开始后的 `occupyChanged` 且没有 `cause` |
| 化身落地加费 | `occupyChanged.cause.timing === 'enter'` |
| 主动 | `battle.activated` |
| 驻场 / 地图重算 | `source` 为 `aura` 或 `map`，用 `auras` / `mapEffect` 点名 |
| 战后 | `settled` |

0 点仍在场上的卡，精灵留在格子上。离场只跟 `cardRemoved`。

## 落地顺序

1. **字段写进聚合，播放器先不动。**  
   完成：用巡猎者、不洗牌、牌序 `PC.A01, PC.A02, PC.A01, PC.A03, …` 打 `MON.N01`。化身格 5，猎犬格 6，结束回合。猎犬的标记事件上 `cause.defId === 'PC.A01'`、`timing === 'turnEnd'`、`op === 'mark'`。紧随的猎犬减点事件上 `cause.defId === 'EC.01'`、`timing === 'turnEnd'`、`source === 'turnEnd'`。食人魔进入格 2 的 `cardEntered` 为 `motion: 'move'`、`from: 3`。`npm run sim -- --compare` 通过，且不重写 `baseline.json`。

2. **战斗场景按序播这些字段，去掉 brief。**  
   完成：同一步的操作下，先看到猎犬的标记收束，再看到食人魔的减点和移动，两下的飘字不同时存在。`effectResolved.hit === false` 的那一拍和打中不是同一个处理函数。

3. **称重、费用、计时、驻场、战后接上插槽。**  
   完成：`turnStarted.won` 才出胜利横幅。化身入场的 +1 费用和回合开始的回满分属两拍。有计时的遭遇（`MON.N03` 的 EC.15）在引爆前能从 `timers` 看到剩余。带竖列或横排驻场的遭遇（`MON.N02` 的 EC.07）减点事件上有 `auras`。`settled.avatarCost` 在结算拍可见。

4. **在插槽里填姿势和音效。**  
   完成标准仍是第 2、3 步的因果，不另加规则测试。

## 不要做

用 `battle.view` 反推施动者、起点格或「这一下为什么是 -5」。

把 `effectResolved` 挪到 op 前面，或新增 `battle.beat` / `battle.cardMoved` 之类 type。那会改基线的 type 序列。

为了演出把一次 `changePoints` 拆成两条领域事件。

在一个 `await` 里同时 tween 两张正在结算的卡。

改 `MON.N01` 的点数或胜负条件。这一轮只让现有结算被看见。
