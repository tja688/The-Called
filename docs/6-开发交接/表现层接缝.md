# 表现层接缝

第 1 层对齐新设计后的冻结合同。`npm run sim -- --compare` 同种子必须与 `src/tools/baseline.json` 逐位一致。

表现层只做三件事：`dispatch(命令)`、`ask(查询)`、按序 `await` 每条事件做演出。读模型是终态快照，不能用来播动画。演出期间锁输入，只留 `Space` 快进。

过程演出的因果字段和串行节拍见 [`战斗过程演出.md`](战斗过程演出.md)。下面的事件表已带上这些字段。

默认像素表现。白模：`?present=dom`。控制台 `called.game`。

类型：只从 `src/application` 引 `GameCommand`、`GameQuery`、`BattleView`、`RunView`。

## 命令

| type | 载荷 | 何时合法 |
| :-- | :-- | :-- |
| `run.start` | `{ seed?; deckId: DK.A\|DK.B\|DK.C }` | 随时。开一趟，所选初始牌组进卡盒和牌组，化身不进卡盒，血 30 |
| `run.abandon` | | 有进行中的一趟 |
| `run.enterNode` | `{ node }` | 地图上，且是正交相邻节点实例 ID |
| `run.setDeck` | `{ deck: string[] }` | 仅地图。卡盒 uid，可含 `PC.N04`。下限 10。负面不能拿掉 |
| `run.eventOption` | `{ index: 0\|1\|2; cardUid?; cardUid2? }` | 事件屏，还没选，选项未置灰 |
| `run.rewardPick` | `{ cardId }` | 奖励屏，且在本次 `pool` 里 |
| `run.shopBuyCard` | `{ index }` | 商店，金币够 |
| `run.shopCopy` | `{ uid }` | 商店，复制卡盒条目 |
| `run.shopBuyRelic` | | 商店，有未拥有遗物 |
| `run.restPick` | `{ choice: 'heal'\|'grow' }` | 疗养，还没选 |
| `run.forgeBuff` | `{ uid }` | 锻造，卡盒一张基础 +2 |
| `run.forgeRecast` | `{ uid }` | 锻造，重铸为同稀有度另一张（可出外系） |
| `run.finishFlow` | | 战斗已 `settled`；或事件已选；或奖励已选；或商店离开；或疗养/锻造已选；或宝箱已开 |
| `battle.play` | `{ card; cell?; target?; target2? }` | 出牌阶段。占场要格；B06 可打己方非化身格；需要指定时加 `target` |
| `battle.endTurn` | | 化身已入场，出牌阶段 |
| `battle.activate` | `{ card; target? }` | 化身在场，本场还没主动过 |

`card` / `target` 是实例 ID（`c1`…）。`deck` 里卡盒条目是 uid（`b1`…），`PC.N04` 是补足。`cardId` 奖励是定义 ID（`PC.A04`…）。

## 事件

每条带 `text` 日志行。`seq` / `stream` 由 EventStore 盖。

### 战斗

| type | 字段 | 建议演出 |
| :-- | :-- | :-- |
| `battle.started` | `encounterId`, `setup[]` | 摆敌阵 |
| `battle.avatarDealt` | `card`, `defId`, `deckLeft` | 化身入手 |
| `battle.cardDrawn` | `card`, `defId`, `deckLeft` | 抽牌飞入手牌 |
| `battle.turnStarted` | `turn`, `opening`, `leading`, `won`, `timers[]` | 先逐张亮 `timers` 剩余。`won` 为真才出称重胜利。开战 `opening: true` 不检查总点数 |
| `battle.phaseChanged` | `phase: play \| over` | 没有压迫阶段 |
| `battle.occupyChanged` | `current`, `cap`, `cause?` | 化身入场 `cause.timing === 'enter'` 是 +1。没有 `cause` 的回满是另一拍 |
| `battle.resourceChanged` | `resource: 'RES.A'`, `current`, `cause?` | RES.A |
| `battle.cardPlayed` | `card`, `defId`, `kind`, `cell?` | 出手 |
| `battle.cardCovered` | `victim`, `by`, `cell`, `victimPoints`, `tied?` | 压扁被盖者；平点双方离场。先于离场和落地 |
| `battle.cardEntered` | `card`, `cell`, `covered`, `motion: place\|move`, `from?`, `cause?` | `place` 落地。`move` 从 `from` 走到 `cell` |
| `battle.cardRemoved` | `card`, `defId`, `cell`, `to`, `reason`, `cause?` | `cover \| effect \| tie \| stack \| link` |
| `battle.pointsChanged` | `card`, `before`, `after`, `source`, `cause?`, `vulnerableBonus?`, `auras?`, `mapEffect?` | 飘字。`source` 是这次结算的时机。易伤加成在同一条里先基础再加成。`aura` / `map` 用贡献列表点名 |
| `battle.statusAdded` / `statusRemoved` | `card`, `status`, `cause?` | `sealed \| marked \| vulnerable \| protected \| rebirth`。保护挡住伤害时只有 `statusRemoved` |
| `battle.effectResolved` | `card`, `defId`, `timing`, `cell?`, `hit` | 本时机收束，留在 op 之后。`hit` 为假是更短的空收束 |
| `battle.activated` | `card`, `defId` | 主动触发 |
| `battle.settled` | `outcome`, `reason`, `avatarCost` | `reason: lead \| clear \| avatarGone \| noPlay`。化身代价是初始减终局 |

不再发出压迫阶段或领先撑一轮事件。

## 视图

`BattleView` 可直接绑 UI：

- 格 1–9：`card?`、是否角落
- 每张实例：owner、zone、cell、基础/当前点、状态、是否化身
- 手牌、牌组剩余、己方弃牌数、敌方弃牌数
- 占领费用 occupy/occupyCap、RES.A、双方总点数、回合、阶段
- 化身：在场？当前点？化身代价预估
- `mustPlaceAvatar`、`canEndTurn`、`canActivate`、`result?`

`RunView`：血、金币、卡盒条目（uid）、牌组、遗物、开局牌组、化身基础、本层地图效果、玩家坐标、节点、屏幕、事件选项（含 enabled）、奖励池、商店。

## 场景路由

跟 `run.screen`：

| screen | 场景 |
| :-- | :-- |
| （未开局） | Title（三选 DK.A / DK.B / DK.C） |
| `map` | Map + 卡盒编组 |
| `event` | Event，选完 `finishFlow` |
| `reward` | 奖励三选一，选完 `finishFlow` |
| `shop` / `rest` / `forge` / `chest` | 对应节点 |
| `battle` | Battle。`settled` 后 `finishFlow` |
| `over` | Ending |

节点是第 1 层 18 格生成图，不是余桩→抽屉→剥手→守门。

## 关键时序

每回合：解封 → 计时 → 回合开始效果（玩家格 1→9，再敌方格 1→9）→ 总点数检查（开战跳过）→ 占领费用按场上己方占场/化身回满（开战为 0）→ 抽 1（开战跳过）。

化身入场立刻 +1 可用占领费用。封印仍提供占领费用，总点数计 0。

回合结束：玩家格 1→9，再敌方格 1→9。没有压迫阶段。

清场立刻胜。无牌可出只看牌组空且手牌没有费用够的卡。
