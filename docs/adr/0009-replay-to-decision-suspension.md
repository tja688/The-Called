# 效果结算以"重放到决策点"的方式暂停

效果解释器与脚本能力都写成顺序执行的代码。结算中途需要真人回答而答案尚未给出时，内核中止执行，回滚到本次结算开始前的快照，并挂出待决策；收到答案后从头重新执行，已经给出的答案按顺序直接取用。怪物 AI 与模拟 bot 在执行过程中同步回答，不会触发中止。这样效果代码能与卡面文字一一对应；暂停时的完整状态只是"一份快照加一串已给答案"，复制、存档、AI 搜索都可以直接使用。

## Considered Options

- 协程（C# 迭代器在决策点让出）：最好读，但暂停中的迭代器无法复制与序列化，与 AI 搜索和中途存档冲突。
- 显式结算栈（把执行拆成可序列化的步骤帧）：随时可复制，但效果逻辑被切成状态机，最难读。

## Consequences

- 依赖 ADR-0002 的确定性：同一次结算重复执行必须产生完全相同的结果。
- 已经发给表现层的事件，在重新执行时不会重复发送。
