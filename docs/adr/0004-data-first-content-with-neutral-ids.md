# 内容以数据描述，并以与虚构无关的内容 ID 标识

卡牌、卡背、怪物技能等内容用数据描述：每条效果都是一条由有限积木（触发时机、生效区域、条件、目标选择、动作）拼成的能力，只有极少数一次性的特例以具名脚本能力在代码中注册。卡牌定义不分阵营，"己方/敌方"相对于持有者解析。内核代码与内容数据只使用与虚构无关的内容 ID，名称、卡面文字、美术与音效全部由各端的主题提供，因此网页端与 Unity 端可以讲完全不同的故事，而共用同一套规则。

命名边界只有一条：换主题时会改名的是内容，用中性 ID，包括卡牌、卡背、怪物、关卡、体系、词条、状态与资源；换主题也不会变的规则骨架，例如格位、点数、覆盖、手牌、弃牌堆、出牌机会、回合，在代码中使用描述功能的英文名。这样代码本身就是规则，人或 AI 读代码就是在读设计；具体内容则经"策划工作名"主题还原成可读的名称。

## ID 格式

内容 ID 形如"类别.编号"，编号一经分配永不复用，例如 `card.c023`（可收集卡）、`card.m001`（怪物专用卡）、`card.t001`（只能被生成的衍生卡）、`back.007`、`monster.003`、`status.004`、`resource.001`。卡面文字默认由能力数据加上主题中的词条名自动生成，各主题可以逐张覆盖为手写文案。

## Considered Options

- 卡牌即代码（每张卡一个类）：改卡要重编内核，策划无法在网页端直接调整，也无法从定义推导卡面文字与负荷报价。
- 嵌入脚本语言编写效果：两端都要携带脚本引擎，批量模拟变慢，效果无法静态分析。
