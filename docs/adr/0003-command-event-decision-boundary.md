# 内核与外壳之间是"决策进、事件出"的消息边界

内核同步推进，直到出现待决策或对局结束，然后输出一串有序且带起因的领域事件；表现层按自己的节奏播放动画，内核从不等待表现层，表现层也从不自行判断合法性。所有输入都是对当前唯一待决策的回答，真人界面、怪物 AI 与模拟 bot 是同一接口下的不同决策者。边界以 JSON 消息定义，与传输方式无关：Unity 中是进程内调用，浏览器中是调用 WebAssembly，开发期网页还可以经 WebSocket 连接本地 .NET 进程以便断点调试。

## 表现层的自由

内核只是生产者，表现层对演出拥有完全的编排权：内核一次交出整批事件，表现层可以看完整批再编排，允许在同一起因内调整顺序、合并（如把"点数 -3"与"随后被移除"合成一次碎裂）、延迟、跳过或追加演出。开发版本中存在一项只读核对，但受以下限制：

- 发现不一致只写一条开发日志，永不修改画面，不跳变，不弹窗。
- 只在轮到真人决策、且演出全部播完的静止时刻核对。
- 只核对逻辑事实（哪格有哪张卡、归谁、显示的点数、手牌、亮出的意图），不核对位置、透明度、动画进度等视觉状态。
- 正式版本中不存在这段逻辑。

之所以写下这些限制，是因为此前的项目中强制表现层与逻辑对齐，造成了难以处理的画面跳变；核对只能是断言，绝不能演变成控制。

## Considered Options

- 表现层对比前后快照自行求差：丢失因果与先后顺序，卡牌动画难以编排。
- 内核在关键节点回调表现层并等待动画：内核被渲染时序绑住，无法无头运行，也难以双端复用。
