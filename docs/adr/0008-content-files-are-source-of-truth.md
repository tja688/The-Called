# 内容文件是数值与效果的唯一依据

卡牌、卡背、怪物等内容以 YAML 文本文件编写并经过结构校验，内核与各端加载同一份数据。内容文件建立后，点数、负荷与效果一律以内容文件为准；策划案只保留规则与设计意图，卡表从内容文件生成，不再手工维护。选择文本文件而不是 Excel + Luban，是因为能力是层层嵌套的树状结构，塞进表格会退化成单元格里的迷你语言，或者拆成大量子表。

## Considered Options

- Excel + Luban：适合数值列，不适合树状的能力。
- 用 C# 代码编写内容：类型安全，但失去热重载，策划改卡必须重新编译。

## Consequences

- 修改策划案里的卡表不会影响游戏；要改数值或效果，必须改内容文件。
- 内核只解析宿主交来的目录文本，不自己读取文件或嵌入资源（ADR-0011）。
- 有了结构化数据，可以按第 06 篇的公式做负荷报价检查，发现卡牌负荷与公式不符时报警。
